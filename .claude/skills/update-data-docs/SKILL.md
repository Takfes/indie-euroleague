# Update Data Docs

## Overview

`docs/data-catalogue.md` and `docs/data-graph.md` are marked "GENERATED —
do not edit" but there is no parsing script behind that banner: the actual
headers are free-form prose (wrapped across lines, dataset names implied
rather than tagged), which makes them a poor fit for a regex parser and a
good fit for an agent that reads them the way a human would. "Generated"
here means *regenerated by this skill*, not by a deterministic script —
don't build one; read the headers and rewrite the two docs directly.

## When to Use

- A script's `Inputs:` / `Outputs:` / `Final:` header changed (new script,
  renamed dataset, renamed raw-data directory, new consumer).
- Before any commit whose diff touches a script header (`AGENTS.md`
  Definition of done: "Script I/O headers current; catalogue + graph
  regenerated").
- The graph or catalogue looks stale, incomplete, or was hand-edited by
  mistake and needs reconciling back to the actual headers.

## Procedure

### 1. Collect every header

```bash
grep -rn -A4 '^Inputs:' src/eupy --include='*.py'
```

Every script with an `Inputs:`/`Outputs:`/`Final:` block belongs in both
docs. Shared library modules with no such block (e.g. `matching.py`,
`player_crosswalk.py`, `team_crosswalk.py`) are excluded — they're not
pipeline steps.

### 2. Derive each dataset's name and stage

- **Name**: for a raw dataset (`data/raw_data/...`), the name is
  `<source-dir>/<logical-name>` — the source directory as declared, plus a
  logical name derived from the file(s) it writes (singularize away any
  `{season}`/`{utc_timestamp}`/templated part: `schedule_{season}.csv` →
  `schedule`; a directory of per-run delta files → the directory's own
  name, e.g. `box_score`). For a produced dataset (`data/stage_XX/...`),
  the name is the file stem.
- **Stage**: raw datasets (no script produces them, only an external
  source) are stage 0. A produced dataset's stage is `max(stage of every
  input dataset) + 1`. Two datasets produced by scripts with no dependency
  between them can share a stage — stage is about the dependency depth, not
  a running count.

### 3. Rewrite `docs/data-catalogue.md`

Three tables, in this order — match the existing file's exact column sets
and phrasing style (skim the current version first, this isn't a from-
scratch format):

1. **Raw datasets** — Dataset, Path, Produced by, Consumed by, Refresh.
   "Consumed by" lists every script whose `Inputs:` names this dataset;
   `—` if none yet.
2. **Produced datasets** — Dataset, Stage, Path, Produced by, Inputs,
   Final, `stage_99` symlink (`data/stage_99/<name>.csv` if `Final: true`,
   `—` otherwise — note when the file doesn't exist yet, e.g. before a
   script's first run).
3. **Scripts** — Script path, Inputs (dataset names, not raw paths; CLI
   flags noted parenthetically), Outputs (dataset names), Final.

Keep the free-text notes below each table (kaggle files not yet referenced,
column notes for multi-output scripts, the `apply_*_verdicts.py` in-place
caveat) — update them if a header changed in a way that affects them,
otherwise leave as-is.

### 4. Rewrite `docs/data-graph.md`

A single `mermaid flowchart LR` with four node groups, declared in this
order:

1. **External sources** (rounded `(["..."])`) — one per distinct upstream
   named in an `Inputs:` block with no producing script (a live URL,
   "Kaggle (manual download)", "verdicts JSON (--verdicts)", "manual
   preparation").
2. **Scripts** (rectangle `["..."]`) — one per header-bearing script,
   short id, e.g. `f_sched` for `fetch_euroleague_schedule`.
3. **Raw datasets, stage 0** (cylinder `[("...<br/>stage 0")]`).
4. **Produced datasets** (rectangle `["...<br/>stage N")]` normally,
   double-bordered `[["...<br/>stage N · final"]]` when `Final: true`).

Then edges: external/dataset → script → dataset, following each script's
actual Inputs/Outputs. Then a `%% stage coloring` block at the end:

```mermaid
classDef external fill:#e8e8e8,stroke:#888888,color:#333333
classDef script fill:#dbe9f6,stroke:#5b84a3,color:#1a2b3c
classDef stage0 fill:#fde9d9,stroke:#c97f3a,color:#4a2c0a
classDef stage1 fill:#dcecdc,stroke:#5a9c5a,color:#1e3a1e
class <external node ids> external
class <script node ids> script
class <stage-0 node ids> stage0
class <stage-1 node ids> stage1
```

If a stage 2 ever appears, add `classDef stage2` (pick a fourth distinct
hue) and a matching `class` line — don't reuse `stage1`'s color for a
different stage. Verify coverage before finishing: every declared node id
must appear in exactly one `class` line, and every id in a `class` line
must be a node declared above it (no typos, nothing orphaned):

```bash
python3 -c "
import re
content = open('docs/data-graph.md').read()
mermaid = content.split('\`\`\`mermaid')[1].split('\`\`\`')[0]
declared = set(re.findall(r'^\s*([A-Za-z_][A-Za-z0-9_]*)[\[\(]', mermaid, re.M))
classed = set()
for line in re.findall(r'class ([A-Za-z0-9_,]+) \w+', mermaid):
    classed.update(line.split(','))
print('missing color:', declared - classed)
print('typo (classed but not declared):', classed - declared)
"
```

Both sets must print empty.

### 5. Verify against the catalogue

The two docs must agree: every dataset in the graph appears in the
catalogue with the same name and stage, and vice versa. Cross-check by eye
— there's no automated diff for this.

## Common Mistakes

- **Writing a regex parser instead of reading the headers.** The prose
  isn't structured enough to parse reliably (see Overview) — this has been
  tried implicitly by hand across several PRs and the fragile part was
  never the reading, it was forgetting to update one of the two docs.
- **Deriving a dataset name mechanically from the file path.** `schedule_
  {season}.csv` is not the dataset name `schedule_{season}`; strip the
  template. A directory of per-run files (live deltas) is one dataset named
  after the directory, not one row per file.
- **Reusing a stage's color for a different stage**, or leaving a new node
  uncolored — run the coverage check in step 4 before finishing.
- **Hand-editing only one of the two docs.** They're generated together in
  one pass; a graph/catalogue mismatch is worse than both being stale.
